нужно спланировать v0.13

основная цель: страница редактирования тегов.

- не совсем понятно, должна ли ссылка Tags быть сверху (где Bookmarks) или снизу где Tools.
- страница должна быть отдельным срезом
- когда она открывается, то показывается список тегов в порядке популярности (то есть можно переиспользовать апи /api/tags)
- сами теги на этой странице не должна визуально повторять теги со страницы списка закладок. это отдельная страница
- каждый тег в списке выглядит так: количество закладок использующих тег, название (name) тега. название тега является ссылкой, ведущей на `${APP_BASE_PATH}/t/${encodeURIComponent(tag.nameLower)}`
- при наведении на тег отображаются две иконки (из lucide): редактирование тега и удаление тега.
- нажатие удаления тега вызывает браузерный диалог подтверждения
- редактирование открывает здесь же диалог редактирования
- над списком тегов отображается текстовое поле для фильтрации (фильтрация только на клиенте, простой includes)
- над списком также отображается количество закладок без тегов и кнопка показать. ее нажатие здесь же отобразит заголовки этих закладок (а ссылка будет вести на страницу редактирования этой закладки)

редактирование тега позволяет:

- изменить тег (типа чтобы тег ai стал тегом AI, т.е. меняется только name)
- заменить один тег на другой (tag1 станет tag2)
