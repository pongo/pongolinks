# Add Bookmarklet Support

## Context

pongolinks is a personal Bookmark library. v0.11 adds a Bookmarklet so a user can start saving the current browser page without manually copying its URL and title into the app.

Relevant existing behavior:

- Bookmark creation currently lives at `/bookmarks/new`.
- The frontend app is served under `/pongolinks` in production.
- Backend API routes are grouped under `/pongolinks/api`.
- `BookmarkUrl` accepts only absolute `http://` and `https://` URLs.
- A URL can identify at most one Bookmark.
- Related Links are extracted from Bookmark descriptions and belong to the Bookmark that contains them.

## Problem

Creating a Bookmark from the current browser tab is still manual. The user must copy the page URL, open pongolinks, create a Bookmark, paste the URL, and fill the title.

The Bookmarklet flow also introduces ambiguity that the manual form does not address:

- Marketing parameters may be present in the captured URL.
- The exact URL may already be saved as a Bookmark.
- The same URL may already exist with the opposite `http`/`https` protocol.
- The URL may already appear as a Related Link in one or more existing Bookmarks.

## Direction

Add a frontend-only Tools section at `/tools` with a draggable Bookmarklet link named `PL`.

The Bookmarklet opens the canonical create route in a new tab:

```text
/bookmarks/new?url=...&title=...
```

The Bookmarklet href is generated by the current pongolinks instance as an absolute URL, including the app base path, instead of deriving the target from the page where the Bookmarklet runs.

When `/bookmarks/new` receives a `url` query parameter, the frontend treats it as a Bookmarklet-assisted create flow:

1. Parse and trim the incoming `url` and `title`.
2. If the URL is not absolute HTTP(S), skip duplicate checking and show the create form with URL focus.
3. Use `tidy-url` in the frontend to compute a cleaned URL.
4. If the cleaned URL differs, show original and cleaned URLs with URL-aware diff highlighting and let the user choose one by clicking it.
5. Check the chosen URL through the backend search slice.
6. Route the user to edit an exact existing Bookmark, warn about alternate-protocol Bookmarks, list Related Link matches, or show the create form.

`tidy-url` is a dependency of `@pongolinks/frontend` only. URL cleanup is UX policy for this flow, not backend normalization and not a domain invariant.

## Backend Search Slice

Add a vertical slice:

```text
apps/backend/src/features/search/
  contracts.ts
  routes.ts
  search-repository.ts
  search-api.test.ts
```

Expose `GET /search/check` inside the backend `/api` group. The effective HTTP route is:

```text
/pongolinks/api/search/check?url=...
```

The endpoint accepts exactly one candidate URL, validates it with `BookmarkUrl.from(query.url)`, and returns existing `bookmark.url_*` errors for invalid input.

Contract:

```ts
type BookmarkUrlCheckResult =
  | { status: "exact-bookmark"; bookmark: BookmarkUrlCheckBookmark }
  | { status: "alternate-protocol-bookmark"; bookmark: BookmarkUrlCheckBookmark }
  | { status: "related-link"; bookmarks: BookmarkUrlCheckRelatedBookmark[] }
  | { status: "not-found" };

type BookmarkUrlCheckBookmark = {
  id: number;
  url: string;
  title: string;
};

type BookmarkUrlCheckRelatedBookmark = {
  id: number;
  url: string;
  title: string;
};
```

Resolution priority:

1. Exact Bookmark URL match.
2. Alternate-protocol Bookmark URL match.
3. Related Link matches, including exact and alternate-protocol variants without mentioning alternateness.
4. Not found.

Alternate-protocol matching is strict: only `http:` <-> `https:` changes. Host, path, query string, hash, slash shape, and all other characters must match exactly.

Related Link matches can return multiple Bookmarks. Sort them by Bookmark `updatedAt desc, id desc`, matching the Bookmark list ordering. Show Bookmark title as the primary clickable label and the primary Bookmark URL as secondary context.

## Frontend Flow

Add:

```text
apps/frontend/src/features/search/
  api.ts
  types.ts

apps/frontend/src/features/tools/
  views/ToolsView.vue
```

Route additions:

- `/tools` renders the Tools page.
- `/bookmarks/new` remains the canonical create route for both manual and Bookmarklet creation.

Update the Bookmark list footer to link to `/tools`.

Keep the Bookmarklet-assisted create flow inside `CreateBookmarkView` as an explicit state machine rather than adding separate routes for each step:

```ts
type CreateBookmarkState =
  | { kind: "manual-entry" }
  | { kind: "choose-url"; originalUrl: string; cleanedUrl: string; title: string }
  | { kind: "checking"; url: string; title: string }
  | { kind: "duplicate-bookmark"; matchKind: "alternate-protocol"; bookmark: BookmarkUrlCheckBookmark }
  | { kind: "related-link-matches"; bookmarks: BookmarkUrlCheckRelatedBookmark[] }
  | { kind: "create-form"; initialUrl: string; initialTitle: string; closeAfterCreate: boolean };
```

Exact Bookmark matches should automatically `router.replace` to `/bookmarks/:id/edit`.

Alternate-protocol matches should show the existing Bookmark URL as the primary action to edit that Bookmark, plus a secondary "Create a separate Bookmark with this URL" action.

Related Link matches should show all matching Bookmarks with edit links, plus a secondary "Create a new Bookmark anyway" action.

For invalid or non-HTTP(S) incoming URLs, skip `search/check`, show the create form, preserve the incoming URL, and focus the URL field.

For empty or missing incoming title, leave Title empty and let normal create validation handle it on submit. For non-empty title, trim it before using it as the initial form value.

After successful creation:

- If the flow started with a `url` query parameter, attempt `window.close()`.
- If the tab remains open after a short tick, fall back to `router.push("/")`.
- Manual `/bookmarks/new` creation continues to navigate to `/`.

## Bookmark Form Changes

Extend `BookmarkForm.vue` narrowly:

```ts
props: {
  bookmark?: BookmarkDTO;
  initialValue?: EditableBookmarkPayload;
  initialFocus?: "url" | "tags";
}
```

Behavior:

- Edit mode uses `bookmark`.
- Manual create mode uses an empty form and focuses URL.
- Bookmarklet create mode uses `initialValue` and focuses Tags.
- If `bookmark` and `initialValue` are both passed, treat it as a programmer error.
- Focus is manual via Vue refs and `nextTick`, not HTML `autofocus`.

## URL Diff

Do not add a diff library in v0.11.

Implement URL-aware frontend highlighting:

- Parse original and cleaned URLs with `new URL(...)`.
- Compare protocol, hostname, pathname, search params, and hash.
- Highlight removed or changed query parameters clearly.
- If `tidy-url` changes non-query URL parts, highlight those parts coarsely rather than doing character-level diff.
